# xstash v2.0.0

xstash is now a Go CLI for saving X bookmarks and likes to local SQLite and exporting them for analysis. It remains read-only on X.

**This is a breaking release.** Go uses a new database; Deno archives are not migrated or modified. Keep your old archive and use the [migration guide](https://github.com/hayatky/xstash-cli/blob/v2.0.0/docs/migration-v2.md) before replacing v1 commands or automation.

## What's new

- Bookmark and like relations share one post store, with durable processing state per post and purpose.
- Default initial sync saves 100 recent bookmarks and 50 likes. Later runs use five-item pages and stop at a known relation. Page and quote limits keep work bounded; a completed window does not mean all history is imported.
- Quotes are cache-first and queued durably. Author/media enrichment is optional; `--media` also downloads files.
- OAuth PKCE and refresh-token safeguards reject stale environment overrides and stop on uncertain rotation. Linux/macOS can import newly issued public-client user grants through hidden prompts; Windows uses `config init`.
- Explicit database creation and offline integrity checks avoid silently creating an empty replacement archive.
- JSON export schema `2.0.0`, updated Markdown/CSV exports, and `xstash --version`.

## Cost and compatibility

Sync can incur X API charges. There is no monthly hard stop: removed budget/cycle flags and old config values do not enforce a spending limit. `stats` reports local estimates and uncertain reservations, not actual invoices. Verify rates and owned-read eligibility in the Developer Console before syncing. Optional enrichment adds API work and requires a configured media price.

Reauthenticate rather than copying Deno credentials. Actual like/bookmark times are unavailable: exported `operated_at` is `null`, and date filters use local discovery times. Update export consumers and agent workflows for the new schema and per-purpose completion commands.

Offline tests do not verify live X API behavior, actual billing or every target OS at runtime. See the [README](https://github.com/hayatky/xstash-cli/blob/v2.0.0/README.md) for full sync limits, authentication recovery and durability caveats.
